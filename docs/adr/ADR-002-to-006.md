# ADR-002 s.d. ADR-006

## ADR-002: PostgreSQL (OLTP) + ClickHouse (OLAP)
- **Status**: Accepted (pending spike S-07 untuk MV & dedup token)
- **Konteks**: dashboard sangat agregatif (timeline, top N, word cloud, geo) atas jutaan post; larangan analytics dari raw table.
- **Keputusan**: konfigurasi & state transaksional di Postgres (RLS). Konten, match, dan agregat di ClickHouse dengan Materialized View ke tabel `agg_*`.
- **Alternatif ditolak**: Postgres + TimescaleDB continuous aggregates — lebih sederhana (1 DB) dan layak untuk skala kecil; dipilih ClickHouse karena kebutuhan skala & kolumnar. Jika tim ingin memulai lebih ramping, TimescaleDB dapat jadi opsi MVP **selama** port `AnalyticsReader` dipertahankan agar migrasi tidak menyentuh core.
- **Konsekuensi**: dua sistem DB untuk dioperasikan; konsistensi eventual antara run state (PG) dan data (CH).

## ADR-003: Worker Python terpisah
- **Konteks**: instagrapi = Python; ekosistem NLP Indonesia dominan Python; aturan: unofficial API tidak boleh jalan di API server.
- **Keputusan**: `worker-fetch-py` & `worker-ai` sebagai container terpisah, berbicara via queue + JSON Schema bersama; routing tetap di Bun.
- **Konsekuensi**: dua bahasa; kontrak di-generate (TS → JSON Schema → pydantic) untuk mencegah drift.

## ADR-004: BullMQ di Redis, di balik port `JobQueue`
- **Konteks**: butuh delay, retry, prioritas, DLQ, interop TS/Python.
- **Keputusan**: BullMQ (TS & PyPI) bila lulus spike S-03/S-04; fallback Redis Streams.
- **Konsekuensi**: Redis wajib `noeviction` + AOF; rate limit provider tidak memakai fitur queue.

## ADR-005: Post global, match per tenant
- **Konteks**: tenant berbeda sering memantau isu yang sama; data sumber publik.
- **Keputusan**: `posts` global (dedupe `(platform, post_id)`), `topic_match_events` ber-`tenant_id`. Enrichment per post di-cache lintas tenant.
- **Konsekuensi**: hemat storage & biaya AI; penghapusan konten spesifik berdampak ke semua tenant (sesuai kewajiban hukum). ~~Crawl belum di-share antar tenant di v1~~ — **diperbarui 2026-09-28:** share crawl dipromosikan ke near-term oleh ADR-009 (collection stream).

## ADR-006: Local AST matcher sebagai sumber kebenaran semantik query
- **Konteks**: kemampuan boolean search berbeda antar provider.
- **Keputusan**: provider hanya dipakai untuk *recall* (term positif); presisi ditentukan matcher lokal atas AST asli.
- **Konsekuensi**: hasil konsisten saat failover; potensi fetch lebih banyak (biaya) untuk query dengan `NOT` — terlihat di cost estimate.
