# H-06 DR drill — 2026-10-04 (server demo single-node)

**Skrip:** `scripts/backup.sh` → `scripts/restore.sh <dir> --pg-db smip_drill --ch-db smip_drill` (database baru, produksi tidak disentuh).

| Langkah | Hasil |
|---|---|
| Backup Postgres (`pg_dump -Fc`, 38.604 baris hidup) + ClickHouse tabel dasar (Native, gzip) | **5 dtk**, 7,5 MB, checksum SHA256 |
| Restore Postgres ke `smip_drill` | **4 dtk** |
| Restore ClickHouse: migrasi skema + insert tabel dasar (agregat & `topic_matches` dibangun ulang MV) | **1 dtk** |
| Verifikasi jumlah baris tabel dasar vs manifest | cocok (posts 10.533, topic_match_events 8.882, engagement_snapshots 11.842) |
| Agregat hasil rebuild vs produksi (`agg_topic_1d`, `agg_topic_1h`, `topic_matches FINAL`, `agg_issue_1h`, `media_items`) | identik (8.638 / 8.638 / 8.638 / 10.574 / 5.554) |
| Postgres (topik, crawl_runs, users, credentials, audit_logs) | identik (8 / 1.785 / 6 / 13 / 1.387) |

**RTO terukur:** restore data ± 5 dtk pada volume ini (+ ± 2 menit mengarahkan layanan ke database hasil restore & restart).
Perkiraan pada 10 kantor × 10 topik × 1 tahun (± 30 juta event): ± 10–20 menit (dominan insert ClickHouse) — ukur ulang saat volume naik.
**RPO:** = jarak antar backup. Rekomendasi: backup **tiap 6 jam** (durasi detik, ringan) → RPO ≤ 6 jam; salinan **di luar server**
(object storage lain / unduh berkala) — keputusan & akun pemilik.

**Catatan:**
- Secret tidak ikut backup: KEK KMS (`KMS_LOCAL_DEV_KEK_B64` / Vault), `.env`, `~/.config/smip/secrets.env` wajib dibackup terpisah;
  tanpa KEK, credential provider di backup tidak bisa dibuka (by design, SECURITY §4).
- Redis tidak dibackup (antrean & cache; job hilang = run dijadwalkan ulang oleh scheduler/reaper).
- Database drill dihapus setelah verifikasi.
